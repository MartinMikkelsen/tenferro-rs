## Current state and correction to the review note

The review note describes an **earlier uncommitted tree**. Commit `e05aad540` already moved `TypedTensor::<T, R>::from_vec_col_major` to unconstrained `impl<T, R>`, stores the original `Vec<T>` without a group, and tests a non-`Copy`, non-`Send`, drop-counted host owner and borrowed view. Preset `Tensor` erasure retains the typed owner rather than reconstructing a group at CPU session dispatch. Do not repeat this migration or reopen its design. The remaining #1903 witness is the actual downstream `Df64` type (fixed and dynamic ranks); the broader D4 host-copy/import/access surface is still incomplete. `HostTensor<T>` in `tenferro-tensor-core` remains in use by explicit external-scalar erasure and must not be removed as part of this phase.

## Large integrated steps

1. **Lock in the generic boundary end to end.** In test code in the existing downstream `ext/df64-proof` crate, use its already-defined `Df64` for fixed- and dynamic-rank `TypedTensor<Df64>` adoption with pointer identity and logical indexing; keep a non-`Copy`, non-`Send` drop-counted witness in the tensor tests. Never add `xprec` (or `df64-proof`) as a normal/build dependency of main crates; no production `Df64` implementation is needed. Preserve the explicit `HostTensor`/`ErasedHostTensor` external path and the existing CPU borrowed-erasure/recycled-output tests. No `TensorScalar` unsealing, public `HostScalar` registration, managed-group conversion, or numerical/AD promises for custom `T`.
2. **Finish the generic host-only operations together.** Reuse existing checked shape/layout and strided-access helpers. Add explicit row-major import and host copy/compaction only where `T: Clone` is needed; expose checked logical access for arbitrary `T` while keeping exclusive mutable borrows. Match D4's `[2,3]` logical-value example. Keep backend/device behavior explicit (no hidden mapping, transfer or group promotion). An infallible `Index`/`Clone` trait on the current default `Dynamic` owner would violate D4; defer those traits until a genuine statically Host-typed representation lands, and state this limit rather than making device owners panic or silently copy.
3. **Integrate and verify as one change.** Run downstream `Df64` witness, non-`Copy` fixed/dynamic, row/column order, strided/empty and error-path tests, the existing CPU pool/erasure regression tests, format and `cargo check -j 16 --workspace --all-targets`. Review the coherent diff; record remaining D1/D4/D10 work and any unavailable checks in the existing #1938 worklog. Keep one branch; no PR for this phase. A matched performance run is needed only if this phase changes performance-sensitive paths beyond straightforward host copying.

## Acceptance boundary

A non-registered downstream scalar constructs and uses `TypedTensor<T, Rank<2>>` and `TypedTensor<T>` without a backend/session/group; a non-`Copy` type is owned and dropped exactly once; host import/copy/index/compaction produce correct logical values under their documented bounds; preset erasure and the CPU recyclable copy path still work. Do not call the *full* #1938 redesign or D1/D4/D10 complete until Host-specialized trait surface and the `HostTensor` fold-in have actually landed and been verified.
