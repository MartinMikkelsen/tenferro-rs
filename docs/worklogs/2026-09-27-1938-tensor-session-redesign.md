# #1938 tensor/session architecture migration

Target contract: [tensor-session-redesign-1938](../design/tensor-session-redesign-1938.md). The #1929 handoff commit `e55c0e17a` is the implementation baseline; this branch is not an integrated-main performance baseline.

## Decisions

- Begin the output side of the shared storage/dispatch/session seam with an owning pooled full-overwrite lease. It owns a handle to the existing shared pool state, not a mutable borrow of the whole pool during kernel execution. Retain its existing checkout accounting and weak return target; do not introduce another allocator or zero uninitialized output.
- Build rank-changing real-view metadata directly into the existing inline-capacity `ShapeVec`/`StrideVec` rather than allocating intermediate `Vec`s. High ranks retain the existing spill behavior.
- The #1903 generic-host review note described an earlier uncommitted state: the unconstrained column-major constructor and plain owner shipped in `e05aad540`. The [next-phase implementation plan](../plans/2026-09-28-1938-generic-host-container-implementation.md) adds a **test-only** downstream `Df64` witness and host-only container copies without adding `xprec` to main crates. Keep checked `get`/`duplicate` on the current `Dynamic` owner; infallible `Index`/`Clone` traits wait for a statically host-typed representation.

## Verification conclusions and constraints

- The CPU basic library tests and doctests passed; a CPU erased-output test demonstrates two simultaneous differently typed leases, safe discard of incomplete scratch, and publication after full initialization. The workspace all-targets check passed after these changes.
- Allocation-counted tests establish zero metadata allocations for small static- and dynamic-rank immutable and mutable complex-to-real views. Existing storage reinterpretation suites pass for both rank modes, including a high-rank spill case.
- Rank-generic borrowed views now enter erased session inputs without allocating metadata for common small ranks or promoting raw host storage into a group. Both raw host slices and existing group-root-backed ranked views are covered, including a real CPU `copy_read_into` session call; the workspace all-targets check passes. This validates the *input borrow*, not a group-free owning tensor or result.
- The first CPU vertical slice now stores ordinary typed host owners directly as column-major `Vec<T>` (including non-`Copy`, non-`Send`, non-preset `T`); preset dtype erasure retains the typed owner rather than rebuilding a group. Backend/explicit representation conversions still use managed groups. A borrowed ranked view enters `copy_read_into` and `to_contiguous_read` without a storage promotion. The latter uses the existing shared output lease and weak recycler, publishes only initialized memory, and returns the allocation to the pool on final drop.
- Focused tests cover owner/view/pointer identity, non-preset destruction, zero metadata allocations for small-rank owner/erasure/borrow, session numerical copy, pool reuse, invalid placement before checkout, ranked-output success and rank-error checkout cancellation. `RUSTC_WRAPPER= cargo test -j 16 -p tenferro-tensor-core -p tenferro-tensor -p tenferro-cpu-basic -p tenferro-cpu --lib --tests` passed (wrapper disabled for trybuild snapshots). The workspace all-targets check passed during implementation; rerun on final diff.
- Bounded 1T CPU performance probe: `view_materialization` tiny transpose (16×16 f64, matching input/layout, explicit `CpuBackend::with_threads(1)` with effective-count assertion), release Criterion, 0.5 s warmup, 1 s measurement, 10 samples. Typed view baseline on this branch: 10.217 µs point estimate; erased borrowed session: 10.902 µs. Both include allocation/copy; this is a same-revision route comparison, **not** a #1929 source-baseline regression/improvement claim. Short sample noise prevents stronger inference. No GPU or multi-thread measurement is claimed.
- The generic host-container phase now covers `Df64` in the downstream proof crate (fixed and dynamic ranks, no registration), non-`Copy` host copies, checked access, explicit `T: Clone` row-major import and strided host compaction; the output is always column-major. The actual downstream test suite, tensor/CPU focused tests and tensor doctests pass; root and downstream all-targets checks pass. A stale erased-size assertion in the downstream proof suite was replaced with its meaningful zero-allocation property: the existing external payload can now dominate the compact typed owner's size. No `xprec` dependency was added to the main crates. The host copy API was not benchmarked; it is explicit O(elements × rank) for strided views rather than a claimed performance improvement.
- This phase does **not** fold `HostTensor` into the typed family, provide Host-specific infallible traits, finish D1–D12 or establish PR readiness: fallible session entry, native-token recovery, GPU ordering, runtime/AD migration and the later integrated performance matrix remain outstanding. #1929 (`e55c0e17a`) remains the post-migration source baseline, not a matched result for this new session benchmark.

## Ownership/representation phase (D1/D2/D5)

- `TypedTensor<T, R, D = Dynamic>` now selects a sealed representation: `Host` (plain/pooled `Vec<T>`), `Gpu` (group-backed root) and `Dynamic` (union). Shape and placement moved onto the tensor; the owned layout is derived from the shape instead of stored beside it. `Tensor` keeps its preset/external payload erasure on the default `Dynamic` representation, and no preset call site changed shape.
- `Host` is the only representation with infallible host access: `as_slice`, `get`/`get_mut`, `Clone` and `Index`/`IndexMut`. `Dynamic` keeps fallible access and remains non-`Clone`, which the existing `typed_tensor_not_clone` UI test and `storage_public_api` source contract still assert. Host-typed construction is spelled `from_host_vec_col_major`/`from_host_vec_row_major` because an inherent method named identically on two impls of a defaulted-parameter type is ambiguous at path-call sites.
- Added checked representation narrowing `into_host`/`into_gpu` (failure returns the unchanged owner) and `Host::promote`, which adopts the same allocation into a group root without copying elements and preserves a pooled return target. Added owning host mappings: infallible `map_read`/`map_write` on `Host`, fallible ones on `Dynamic` (device-only storage reports a typed host-access error). `Gpu` is the group-backed representation, so a host-managed group root is group-backed with fallible host access; recorded in the design doc.
- Tests: 9 new cases in `crates/tenferro-tensor/tests/representation_boundaries.rs` cover pointer-preserving moves, independent cloning, checked versus panicking indexing, explicit row-major import, narrowing failure retaining the owner, promotion without copying, and owning read/write mappings. Focused tensor/tensor-core/cpu suites, tensor doctests, the downstream `Df64` suite, `tenferro-runtime`/`-linalg`/`-einsum`/`-fft`/`-ad` library and integration tests, and `cargo check -j 16 --workspace --all-targets` all pass.
- Consolidating a source owner is now uniform where the design names a conversion. `TypedTensor::try_into_rank` (rank) and `Tensor::into_typed`/`TensorScalar::into_typed` (dtype recovery) return `ReinterpretError` carrying the unchanged owner instead of destroying it on rejection; `Tensor::into_vec_col_major` keeps `crate::Result` but pre-checks the dtype so its recovery call is provably unreachable. Callers that had already checked the dtype (`typed_output` in `tenferro-linalg`, the `cubecl` reshape dispatch) turn the now-unreachable arm into an explicit internal-contract error rather than a silent drop. Three further cases were added to `representation_boundaries.rs` (rank retention, dtype-recovery retention, and a pooled return target surviving `Host::promote`), for 12 cases total.
- Source ownership now survives every rejection in this layer. `TypedTensor::{into_host_vec, into_vec_col_major, into_parts}`, `Tensor::into_typed`, `TensorScalar::into_typed`, `Tensor::into_vec_col_major`, and `TypedTensor::try_into_rank` return `ReinterpretError` carrying the unchanged owner instead of destroying it. Two storage-kernel changes make that possible: `OwnedStorage::into_host_vec` and `AllocationGroup::into_host_vec` now hand the root (and the group) back on rejection. `AllocationGroup::into_host_vec` takes only the allocation and leaves the descriptor in place, so the rejected group is the exact unchanged one; `ReinterpretError::into_parts` was made public so callers can keep the owner and take the typed cause. Callers that had already checked the dtype (`typed_output` in `tenferro-linalg`, the `cubecl` reshape dispatch, one internal-cpu-kernels export) turn the now-unreachable arm into an explicit internal-contract error.
- Tests: 14 cases in `crates/tenferro-tensor/tests/representation_boundaries.rs` cover pointer-preserving moves, independent cloning, checked versus panicking indexing, explicit row-major import, narrowing failure retaining the owner, promotion without copying, owning read/write mappings, rank retention, dtype-recovery retention, device host-export retention (all three exports), erased host-export dtype retention, and a pooled return target surviving `Host::promote`.
- Remaining in this family: a mapping guard now lends a host view. `HostReadGuard::as_view()` returns a rank-1 `TypedTensorView` over the mapped elements, borrowing the guard rather than copying. The write side has no counterpart: `HostWriteGuard` is deliberately write-only (it publishes through `copy_from_slice`), so a `guard.as_view_mut()` would need a distinct read-write mapping contract that neither the guard nor `ProviderWriteMapping` currently provides; that is a provider-level design question, not a missing accessor.
- D10 preparation: the set-wide promotion selection that `define_scalar_set!` used to inline was extracted into a public `tenferro_tensor_core::promote_in_set`, and the macro now delegates to it. The relocated default scalar set needs that function because its value enum cannot be generated by the macro once `HostTensor` leaves core. No behavior changed; the core set tests still pass.
- D10 landed. The host-container family moved out of `tenferro-tensor-core` into `tenferro-tensor`: `HostTensor`, `HostTensorView`, `DefaultScalars` (with its private value enum), the erased host views (renamed `DefaultScalarsView`/`DefaultScalarsRef` because `tenferro_tensor::TensorView` already exists), and `ErasedHostTensor` with its payload trait. `ScalarSet` and `define_scalar_set!` moved with them, because the value enum they build holds a host tensor; core keeps `DType`, `TensorScalar` (now only `Real` + `dtype()`), `define_scalar_tag!`, `MemberKind`/`MemberSpec`/`promote_specs`/`promote_in_set`, and rank/layout validation. Two supporting refactors made that possible: `define_scalar_tag!` was split out of `define_scalar_set!` so core can declare `DType` without a tensor-holding value enum, and the set-wide promotion choice became the public `promote_in_set(tags, specs, lhs, rhs)`, used by both macros and by the relocated set's hand-written `ScalarSet` impl. The relocated code keeps its own copies of five small host-layout predicates and derives `validate_view_bounds` from the public `TensorLayout::from_parts`, so core needed no new public validation API. `crates/tenferro-tensor-core/tests/core.rs` became `crates/tenferro-tensor/tests/host_container_contract.rs` (empty-slice assertions annotated for the dev-dependency set) and `scalar_set_import_forms.rs` followed the set. `ext/scalar-consumer-application` gained `tenferro-tensor` as a library dependency because the declaration macro now names that crate's container.
- The relocation surfaced one real repository contract: `tensor_public_surface_has_no_context_free_materialization_api` forbids a public `to_contiguous` anywhere in `tenferro-tensor/src`, and `ErasedHostTensor::to_contiguous` is host-only container compaction. The design already names this as the exception to the old rule, so the contract test now names it too: the two host-container modules are excluded from the *public materialization name* check while the `include!` ban and forbidden macro identifiers still cover them, and the exclusion holds only while those files contain no `BackendSession`/`BackendSessionHost`/`TensorStructural` identifier.
- Verification after the move: tensor/tensor-core/cpu-basic/cpu focused suites (40), both tensor crates' doctests, the four `ext/*-proof` and consumer suites (37), runtime/linalg/einsum/fft/ad suites (21), `cargo check -j 16 --workspace --all-targets`, workspace clippy `-D warnings`, and the public-error-docs gate.
- Still outstanding from D1: the borrowed views (`TypedTensorView`/`TypedTensorViewMut`) remain the runtime union rather than carrying the `D` parameter, so representation-typed *views* are not done; a `Host` owner's `as_view`/`as_view_mut` already produce host-backed union views. No performance claim is made for the relocation: it moves code between crates and adds no hot-path work.
